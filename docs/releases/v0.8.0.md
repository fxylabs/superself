# Superself 0.8.0: carry complete work state between agents

Superself 0.8.0 gives a fresh agent the project rules, work state, reports, and recovery commands it needs to continue active work. It also lets a person revise an unstarted work proposal without replacing its id.

## Hand active work to a fresh agent

Run:

```sh
self handoff <work-id> [--project <slug>]
```

The command emits one deterministic packet with the common Superself protocol, applicable conventions, bounded project context, complete work and report history, and recovery guidance for the current lifecycle and execution location.

The packet is read-only. The command accepts exact work ids, appends no event, creates no file, and does not start or switch an agent. Project-controlled text stays inside renderer-owned framing so report or convention content cannot become a packet section.

## Revise a proposal before work starts

Run:

```sh
self work revise <id> "<revised plan>" --why "<what changed>"
```

The work id and every earlier plan version remain in the same unit. A revision invalidates the previous acceptance, so a person must accept the new plan before an agent can start it. The first `self work start` freezes the plan; later corrections use a successor work unit.

## Upgrade after publication

After the `v0.8.0` release workflow finishes, install the published package:

```sh

```
